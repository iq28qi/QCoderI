# QCoderI

Переносимое Windows-приложение и основа для собственного проекта на базе DeepSeek Harness 0.1.0-rc.22.

## Репозиторий исходников

Исходники, ресурсы, тесты и лицензии зависимостей доступны без входа в GitHub: [дерево файлов](https://github.com/iq28qi/QCoderI/tree/main/harness-base) · [все исходники одним ZIP](https://codeload.github.com/iq28qi/QCoderI/zip/refs/heads/main). Старая локальная история Git, ключи, чаты, локальные настройки, резервные копии, журналы и скриншоты проверок не публикуются.

В `harness-base/source/**/node_modules` находятся поставленные и изменённые файлы движка, а не обычный восстанавливаемый каталог `npm install`: они являются частью исходного снимка. Не удаляйте и не заменяйте их массовой переустановкой зависимостей. Лицензии сторонних пакетов сохранены рядом с пакетами.

**Клонирование репозитория не устанавливает готовое приложение.** EXE и комплектный Node.js из `harness-base/app/resources/runtime` не публикуются в Git. Текущая сборка `stage-native.py` также предполагает наличие базовой установки с `QCoderI.exe`, комплектным runtime и локально доступными зависимостями Cargo. Сборка с чистого клона пока не автоматизирована; инструкции ниже описывают работу из установленной копии. Все подключения к API настраиваются пользователем отдельно.

## Запуск

Откройте **QCoderI.exe** в этой папке. Оконная оболочка на Rust использует установленный в Windows WebView2. Движок чатов и инструментов запускается на комплектном Node.js. Для переноса скопируйте всю папку QCoderI.

Для перехода с Electron закройте открытое окно прежней версии и запустите корневой **QCoderI.exe**. Обе версии используют одну папку данных. Для повторной сборки запустите `Build-QCoderI.ps1` с установленным Rust и Python.

Настройки, диалоги, вложения и подключения к провайдерам хранятся локально в `harness-base/data` и не входят в репозиторий. На новой установке настройте собственные подключения в интерфейсе приложения; готовые ключи и личная история не поставляются.

Папка `data` содержит личные чаты и ключи подключений. Для публикации собственного проекта используйте исходники без неё и без `backups`; обе папки исключены из Git.

## Что входит

- Русский интерфейс, имя и значок QCoderI.
- Дизайн Moonlight Studio по вашему референсу: ночная фиолетовая палитра, свечение, стеклянные панели, аниме-иллюстрация и орбитальный логотип. Учтены компактное окно, светлая тема и отключение анимаций в настройках Windows.
- Навигация по чату, файлам, терминалу и агентам. Карточки стартовых задач заполняют настоящий черновик; отправка остаётся под вашим управлением.
- Фоновые команды Windows и PowerShell без отдельных консольных окон.
- «Настройки → Системный промпт»: дополнительные постоянные инструкции, сохранение и очистка. Изменения применяются при создании нового живого диалога; уже работающий диалог сохраняет снимок инструкций.
- Полный доступный JavaScript/HTML/CSS-код установленного приложения, зависимости и нативные библиотеки.
- Скрипты повторной сборки и проверки.

## Обновления Rust-версии

Откройте колокольчик внизу боковой панели. QCoderI проверяет настроенный канал при запуске и каждые шесть часов. Доступную версию можно скачать и установить кнопкой **Установить и перезапустить**. Установка ждёт завершения текущих задач. Профиль, история и ключи остаются в папке данных.

Для публикации подготовьте каталог релизов на HTTPS-сервере со стабильными прямыми ссылками. Создайте ключ Ed25519 и храните закрытый ключ вне папки приложения. Для следующего релиза увеличьте версию QCoderI в `harness-base/native/Cargo.toml` и обновите запись пакета `qcoderi` в `Cargo.lock`.

```powershell
openssl genpkey -algorithm ED25519 -out C:\keys\qcoderi-release.pem
openssl pkey -in C:\keys\qcoderi-release.pem -pubout -out C:\keys\qcoderi-release.pub.pem
.\Build-QCoderI.ps1
python .\harness-base\scripts\package-native-update.py --key C:\keys\qcoderi-release.pem
```

Загрузите ZIP из `dist`, затем `latest.json` в ту же папку. На каждой установке один раз создайте `harness-base/update-channel.json` с адресом этого манифеста и открытым ключом. Например, в PowerShell 7:

```powershell
@{
    url = 'https://updates.example.com/qcoderi/latest.json'
    publicKey = Get-Content C:\keys\qcoderi-release.pub.pem -Raw
} | ConvertTo-Json | Set-Content .\harness-base\update-channel.json -Encoding utf8
```

Windows-пакет содержит Rust-окно и версию движка для этого окна. Он не содержит папку пользовательских данных. Ключ канала и ZIP проверяются перед заменой.

Если при первой сборке с поддержкой обновлений окно было открыто, Windows сохраняет новый EXE рядом как `QCoderI.native-build.exe`. Закройте QCoderI и повторно запустите `Build-QCoderI.ps1`, чтобы установить эту сборку под основным именем.

## Общение и проекты

**Общение** — обычный чат с выбранной моделью. Новая переписка открывается без выбора папки; можно задавать вопросы, обсуждать идеи, писать тексты и просто разговаривать. История находится в разделе «Диалоги». Инструменты файлов, терминала и агентов в этом профиле отсутствуют.

**Проекты** — работа с кодом и файлами выбранной рабочей области. Здесь доступны штатные профили агента, команда исполнителей, файловый обозреватель и терминал. Переключатель вверху и кнопки боковой панели позволяют переходить между режимами. «Новый диалог» создаёт обычный чат; новый диалог проекта можно открыть через рабочую область.

Стартовый экран и интерфейс оформлены в одном стиле Moonlight Studio: короткое появление без резких перемещений, спокойные поверхности, светлая тема и компактная раскладка. Уменьшение движения учитывается при запуске и в интерфейсе.

Код интеграции хранится в `assets/studio-*.js`, оформление — в `assets/studio.css`. `scripts/refine-studio.py` воспроизводимо применяет изменения; обычный сборщик вызывает его автоматически. Экран запуска редактируется в `source/renderer/startup.*`.

## Уровень рассуждений

Нажмите имя модели под полем сообщения → **Уровень рассуждений**. Доступные уровни определяются автоматически по данным выбранного API, каталогу и семейству модели с учётом ключа и Base URL. Выбор передаётся параметрами API, сохраняется и наследуется дочерними агентами. **По умолчанию** оставляет выбор серверу. Управление находится только в чате. [Автоопределение и проверки](harness-base/docs/REASONING.md).

## Просмотр фото

Автоопределение применяется ко всем подключениям: отрицательные значения по умолчанию из каталога шлюза не отключают изображения у известной зрительной модели. Учитываются канонические имена, облачные префиксы и псевдонимы. Явный выбор «Только текст» сохраняет приоритет.

Если каталог провайдера ошибочно объявляет зрительную модель текстовой, откройте дополнительные параметры этой модели → **Поддержка изображений → Текст и изображения**. Параметр действует и в существующих диалогах.

Прикреплённые фото передаются моделям с поддержкой изображений, включая пользовательские подключения и алиасы вроде `kimi-k3-1-pro`. Возможности определяются по данным API и встроенному каталогу; для известных семейств предусмотрен резервный выбор при недоступном списке моделей. Явное поле `input` модели в настройках подключения имеет приоритет. Изображения остаются в истории и доступны в следующих сообщениях. [Устройство и проверки](harness-base/docs/IMAGES.md).

В режиме **Проекты** модель сама использует `take_screenshot`, когда нужно проверить или продемонстрировать визуальный результат: интерфейс, сцену, страницу, график или проблему. Отдельная просьба о скриншоте не нужна. Доступны основной экран, все мониторы, активное окно и область. Картинка сразу появляется в чате, открывается крупно и остаётся в истории. [Снимки экрана](harness-base/docs/SCREENSHOTS.md).

Когда работе нужна новая фотография, иллюстрация, фон или текстура, агент использует `generate_image`: основной генератор — **seedream-5.0-pro**, по умолчанию 2K. Для правки одного исходника автоматически выбирается **krea-k3-edit**; сложную правку или несколько референсов можно поручить Seedream. Используются подключение и ключ NiceAI. Картинка видна в чате, а созданный файл доступен для копирования в проект. [Генерация изображений](harness-base/docs/IMAGE-GENERATION.md).

## Видео NiceAI

Для `seedance-2.5` и `kling-3.0-pro` используется отдельный API видео NiceAI. Выберите модель, задайте длительность (5/10/15/30 секунд либо своё значение от 1 до 120) и опишите сцену. Приложение покажет статус и добавит большой плеер с результатом в ленту разговора. Плеер показывает реальный кадр, поддерживает перемотку и повтор загрузки. Обычный чат-маршрут для этих моделей не используется.

Поддерживается генерация по тексту. Подробности об остановке ожидания, повторных запросах и проверках — в `harness-base/docs/NICEAI-VIDEO.md`.

Каждый ролик остаётся под своим запросом с превью и кнопками «Скачать» и «Повторить». Новые генерации не скрывают предыдущие результаты. Повтор подставляет исходное описание, модель и длительность в черновик; для запуска нужно нажать «Отправить».

## Команда агентов

**Команда QCoderI** — профиль по умолчанию в «Проектах» на новой установке. Выберите рабочую область и начните диалог. Если ранее выбрали другой профиль, переключитесь через **Агенты → Профили агентов**. В команде доступны инструменты Unreal Engine, Blender, Windows, изображений, файлов, терминала и статического анализа.

Ведущий разбивает задачу на самостоятельные задания и вызывает `team_run`. Одновременно работают до **4 исполнителей**, всего до 12 задач в одном запуске. Можно указать модель каждого исполнителя через `model`; по умолчанию он наследует выбор ведущего. Ход работы виден в дочерних сессиях и фоновых заданиях.

- Независимые задания выполняются параллельно; `depends_on` задаёт порядок зависимых работ и передаёт отчёты предыдущих исполнителей.
- `write_paths` назначает файлы или каталоги. Пересекающиеся пути планировщик обрабатывает последовательно. Режим `workspace_mode: git_worktree` создаёт отдельные копии из чистого Git-репозитория. После проверки результат объединяется в отдельной ветке `codex/qcoderi-team-…`. При конфликте рабочая копия сохраняется. Для проектов без Git используется общая папка.
- `team_status` показывает очередь, статусы и отчёты. `job_output` собирает результат, `job_kill` останавливает команду и её активных исполнителей.
- У каждого задания есть тайм-аут: по умолчанию 10 минут. Неуспешная задача блокирует зависимые задания; независимая работа продолжается.
- Очередь отдаёт приоритет задачам, открывающим длинные цепочки зависимостей. `read_paths` согласует чтение с записью, `resources` координирует общие сборки и другие ресурсы.
- `shared_context` передаёт общие вводные всем исполнителям, `acceptance_criteria` задаёт критерии результата, `tools` позволяет сократить каталог инструментов отдельного исполнителя.
- `checks` запускает команды проверки через штатный PowerShell-инструмент. После ненулевого кода теста исполнитель получает его вывод и может исправить причину. `repair_attempts` задаёт число исправлений от 0 до 2, по умолчанию 1. При окончательном сбое зависимые задачи блокируются. Задачи без команд помечаются как непроверенные.
- «Настройки → Системный промпт» задаёт постоянные рабочие инструкции один раз. Дочерние агенты наследуют снимок ведущего, включая случай изменения настроек во время работы команды.
- `team_control` ставит команду на паузу и возобновляет её в том же чате после остановки или перезапуска. Завершённые задачи сохраняются. `budget_seconds` ограничивает время одного запуска команды. Ведущий получает отчёты и проверяет общий результат.
- `project_memory` хранит подтверждённые решения и соглашения проекта между чатами. `project_context` ищет актуальные фрагменты кода, документацию и пути к 3D-ассетам.

В длинных сеансах QCoderI сокращает объём старых текстовых логов перед запросом к модели. Задание пользователя, вложения, ошибки инструментов и недавние результаты сохраняются в контексте. Полный вывод остаётся в истории. `job_output` возвращает компактный отчёт команды, а `team_status(include_reports=true)` выдаёт подробный отчёт и логи проверок.

Пример запроса: «Добавь авторизацию. Распредели сервер, интерфейс и тесты между исполнителями, затем проверь общий результат». Скорость зависит от независимости задач и лимитов провайдера; параллельные запросы расходуют дополнительные токены.

Код команды хранится в `harness-base/assets/team`. Сборщик устанавливает его в профили «Команда QCoderI» и «3D Studio».

## Управление приложениями и 3D Studio

В **Проектах** доступны управление обычными окнами Windows, поиск элементов интерфейса, ввод текста, сочетания клавиш, клики, прокрутка и перетаскивание. Агент сначала смотрит состояние приложения, выполняет действие и получает снимок для проверки. Для запуска используется `desktop_launch`; для показа готового изображения или рендера — `share_image`. Защищённый рабочий стол/UAC, окна с более высокими правами и некоторые нестандартные интерфейсы имеют ограничения. [Управление приложениями](harness-base/docs/DESKTOP-CONTROL.md).

Для 3D откройте **Агенты → Профили агентов → 3D Studio**, выберите рабочую папку и начните новый диалог. Профиль работает по фото-референсам, добавляет запуск Blender, проверку геометрии и материалов, студийный свет и реальные рендеры. Агенту предписано осматривать несколько ракурсов и исправлять недостатки до передачи результата. Фото можно прикладывать в обычное поле сообщения; рендеры и снимки работы видны в чате. Нужна модель с поддержкой изображений для визуального анализа. [Работа с 3D](harness-base/docs/3D-STUDIO.md).

Для анализа локальных бинарников выберите **Агенты → Профили агентов → Хакер** и укажите рабочую папку. Профиль использует выбранную в чате модель. Агент запускает локальную Ghidra или IDA с IDAPython в фоне, получает секции, импорты и список функций, а затем задаёт вопросы по сохранённой базе: поиск по имени, подстроке или регулярному выражению, по адресу (VA либо RVA), строки, инструкции, вызывающие и вызываемые функции с адресами вызовов, ограниченный граф вызовов и псевдокод декомпилятора (Ghidra decompiler, IDA Hex-Rays). Повторные вопросы выполняет `binary_query` — он переоткрывает готовую базу и не повторяет анализ. Вывод подкрепляется адресом, именем функции и фрагментом инструкций или псевдокода из отчёта, а гипотеза помечается как гипотеза. Установки можно указать параметром `install` либо переменными `QCODERI_GHIDRA_HOME`, `QCODERI_IDAT`; для Ghidra нужен совместимый JDK (`java_home`). Проект анализатора, JSON, журнал и отчёты запросов сохраняются в `QCoderI-Analysis` внутри рабочей папки. [Поля запроса, отчёты и ограничения](harness-base/docs/HACKER.md).

`blender_run(views: true)` автоматически создаёт основной, передний, боковой и задний ракурсы. Отчёт показывает и геометрию после модификаторов. Повторная студийная настройка сохраняет пользовательские объекты. Снимки после действий проверяют ожидаемое окно, чтобы не прикладывать случайно другое приложение. При недоступном подключении генератор проверяет остальные настроенные маршруты NiceAI до создания картинки.

## Unreal Engine 5 и Blueprint

В **Проектах** выбери папку с `.uproject`, создай новый диалог с профилем **Unreal Engine 5** и выбери нужную модель. Профиль добавляет инструменты сцены, меню UMG, шрифтов и графов Blueprint. Первое подключение: «Подготовь мост для этого проекта; движок в `G:/UE/UE_5.7`». Агент устанавливает редакторский плагин с резервной копией `.uproject` и собирает его; после открытия проекта UE команды выполняются прямо в редакторе.

Игра остаётся на Blueprint. Для UE 5.7.4 включён готовый плагин; для другой версии его можно собрать из чата с C++ Build Tools. [Подключение, команды и ограничения](harness-base/docs/UNREAL.md).

## Рабочая панель

Кнопка **Работа** сверху открывает небольшое всплывающее меню по образцу выбора модели. Чат, поле сообщения и выбор модели остаются на своих местах. В ней доступны до четырёх параллельных исполнителей с очередью, уточнениями и отдельной остановкой, передача управления компьютером, память проекта, словарь, текстовый редактор, поиск, Git diff, версии файлов с выборочным откатом и интерактивные отчёты. Диктовка через API или локальный Whisper вставляет проверенный текст в черновик. 3D Studio может отправить реальные ракурсы отдельному проверяющему с ограничением повторов. [Устройство, проверки и ограничения](harness-base/docs/WORKBENCH.md).

Встроенный `imagegen` загружается без внешнего Codex SKILL.md. При явном отказе API прочитать тело запроса предусмотрен один повтор с меньшими копиями изображений; оригиналы сохраняются. Уже начавшийся ответ и вызовы инструментов не повторяются.

## Разработка и сборка

Оптимизация потокового интерфейса: промежуточный текст объединяется в обновления с интервалом 80 мс, ввод черновика изолирован от дерева сообщений, автопрокрутка не запускает повторную отрисовку сама себя. Финальный ответ публикуется сразу. [Измерения и воспроизведение проверки](harness-base/docs/PERFORMANCE.md).

Редактируйте файлы в `harness-base/source`, закройте QCoderI и выполните из PowerShell:

```powershell
python .\harness-base\scripts\build.py
```

Либо запустите `Build-QCoderI.ps1`. Для сборки нужны Python 3.11+, Rust и MSVC Build Tools. Cargo использует зафиксированные в `Cargo.lock` версии. Если доступен `windres`, сборщик встраивает готовый значок приложения.

Основные места для изменений:

- `assets/moonlight.css` — оформление Moonlight Studio; сборщик копирует CSS и иллюстрацию в веб-приложение.
- `docs/MOONLIGHT-DESIGN.md` — устройство дизайна и сведения об иллюстрации.
- `native/src/main.rs` — окно WebView2, запуск и завершение движка.
- `native/desktop-server.mjs` — локальный транспорт чата и озвучивание ответов через системные голоса Windows.
- `source/dsh/node_modules/@deepseek-ai/dsh-client-locale/lib/client.js` — локализация и русский словарь.
- `source/dsh/node_modules/@deepseek-ai/dsh-client-ui-settings-general/lib/client.js` — настройки и поле системного промпта.
- `source/dsh/node_modules/@deepseek-ai/dsh-system-prompt/lib` — сборка инструкций и снимок пользовательского промпта.
- `source/dsh/node_modules/@deepseek-ai/dsh-win32-process/lib/index.js` — запуск процессов через Windows API.
- `source/dsh/node_modules/@deepseek-ai/dsh-client-ui-brand-official/lib/client.js` — название и знак в интерфейсе.

Проверка окна, чата и озвучивания на локальном тестовом провайдере:

```powershell
$env:QCODERI_CHAT_ERROR_UI = '1'
.\harness-base\app\resources\runtime\node\node.exe .\harness-base\scripts\smoke.mjs --native
```

Это извлечённый код поставленной сборки, пригодный для редактирования и повторной упаковки. Исходные TypeScript-файлы, не включённые автором в дистрибутив, здесь не восстановлены. Внутренние имена пакетов `@deepseek-ai/*` сохранены для совместимости их импортов.

Базовый проект и сторонние зависимости сохраняют свои лицензии; они находятся рядом с соответствующими пакетами. Лицензии Electron/Chromium также включены в папку приложения.
