# Управление приложениями Windows

В режиме «Проекты» агент получает инструменты управления обычными настольными приложениями. Для каждого приложения отдельный плагин не требуется: используются Windows UI Automation, стандартные Win32-контролы и ввод мышью/клавиатурой. Специализированный API приложения или скрипт предпочтителен для массовых точных изменений; GUI полезен для остальных операций и проверки вида результата.

| Инструмент | Назначение |
| --- | --- |
| `desktop_inspect` | Без `window` — список окон (включая `desktop: background/default`). С `window` — дерево элементов, подписи, значения обычных полей, границы, временные идентификаторы. `screenshot: true` делает прямой снимок окна без переключения фокуса |
| `desktop_action` | Click/invoke, set_value/type, hotkey, scroll и drag. По умолчанию ввод разрешён только в фоновых окнах. Для действий по явной просьбе пользователя в видимом окне нужен `foreground: true`. Обычно возвращает снимок окна после действия |
| `desktop_launch` | Открытие `.exe` с буквальными аргументами, без командной оболочки. По умолчанию (`background: true`) запускает приложение на изолированном фоновом рабочем столе `QCoderI_Background` без показа пользователю |
| `share_image` | Отправка настоящего PNG/JPEG/WebP/GIF или рендера из файлов проекта в чат и модели |

Модель получает инструкцию сама исследовать приложение и делать короткие проверяемые шаги в рамках текущей задачи. Элементы берутся из свежей инспекции; координаты — абсолютные пиксели рабочего стола, в том числе отрицательные на других мониторах. Для традиционных контролов есть запасные идентификаторы `hwnd:...`, чтение/запись текстового поля и вызов кнопки. Парольные значения не читаются. Произвольный текст передаётся Unicode-вводом, а не исполняется как PowerShell/SendKeys-код.

Координатное действие проверяет границы окна и приложение в указанной точке. Перед отправкой клавиш проверяется фактический фокус; при изменении состояния агент должен снова инспектировать окно. Неопределённое действие автоматически не повторяется. Ввод — [Windows SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput), доступные семантические действия — [UI Automation patterns](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/ui-automation-control-patterns-overview).

Это не обещание управления абсолютно любым окном. Windows не допускает обычный ввод в защищённый рабочий стол/UAC и может блокировать его для программ с более высокими правами. Игры, удалённые сеансы, нестандартные canvas-интерфейсы и занятые приложения могут не предоставлять дерево элементов; тогда остаются снимки и координаты, если приложение принимает ввод. Автоматического повышения прав или обхода этих ограничений нет. Итог действия нужно проверять по приложению.

Изображения из `desktop_*` и `share_image` сохраняются штатным AttachmentStore и показываются открытыми карточками в ленте. Они доступны после повторного открытия диалога. Текстовая модель может пользоваться деревом интерфейса и отправлять картинки пользователю, но для визуального анализа нужна image-capable модель. «Общение» остаётся без инструментов компьютера.

Снимок после действия и в `take_screenshot(target="window", window=...)` снимается напрямую с указанного окна (в том числе на фоновом рабочем столе) без переключения пользовательского фокуса; для legacy `active_window` с указанным `window` также выполняется прямой захват окна. Ошибки захвата показываются коротким сообщением без служебной команды PowerShell.

Код: `assets/team/desktop.js`, `desktop-driver.ps1`, `screen-capture.js`; сборка подключает `@qcoderi/team/desktop` к настольному хосту. Временный PowerShell-код материализуется из архива в кеш скриптов; ключи API и пользовательский текст в него не встраиваются. Фоновые помощники не открывают консольных окон; запрашиваемое приложение по умолчанию запускается в скрытом рабочем столе (`background: true`), а видимый запуск на основном экране включается только при `background: false`.

`tests/desktop-native.mjs` по умолчанию использует невидимое тестовое окно: проверяет инспекцию, реальный Unicode set_value, нажатие стандартной кнопки и устаревший идентификатор. Настоящий AgentLoop отдельно проверяет результат инструмента с изображением, отправку файла и отсутствие доступа из обычного чата. Интерактивные мышь/клавиатура требуют явного `QCODERI_DESKTOP_INTERACTIVE_TEST=1` и видимого тестового окна; этот интерактивный прогон не завершён. Проверка не меняет пользовательские приложения.
