# Оптимизация потокового интерфейса

Проверено 4 ноября 2026 на Windows, на отдельном временном профиле Electron. Рабочий профиль пользователя и текущие задачи не останавливались.

## Причины лишней работы

Публикация промежуточного текста ожидала три кадра `requestAnimationFrame`. На быстрых экранах это давало более частую сборку и отрисовку растущего Markdown, чем на 60 Гц. Автопрокрутка дополнительно обрабатывала собственные события как повод повторно отрисовать весь ChatView. Ввод черновика также затрагивал дерево переписки и медиа-контекст через новые ссылки на callback.

Изменения:

- Промежуточные публикации объединяются в окно 80 мс, затем публикуются в ближайшем кадре. Каждая дельта принимается сборщиком; финальные и структурные события немедленно снимают ожидание и публикуют актуальное состояние. Скрытая страница использует окно 250 мс и не зависит от остановленного кадрового таймера.
- Отмена и освобождение привязки очищают и таймер, и ожидающий кадр.
- Собственное событие автопрокрутки не запускает дополнительный React render. Настоящая прокрутка читателем сохраняет прежнюю обработку и владение позицией.
- Элементы сессии и активного представления сохраняют ссылки при вводе черновика; обработчик повтора видео стабилен, пока его зависимости не меняются. Подписки самой переписки продолжают получать потоковые обновления.

Патч воспроизводится `scripts/optimize-runtime.py` после `scripts/refine-studio.py`; обычный `build.py` вызывает оба. Повторное применение проверено. Оформление и число исполнителей не менялись.

## Сравнительный запуск команды

`tests/ui-performance.mjs --team` использует настоящий AgentLoop, `team_run`, четыре дочерних исполнителя и локальный OpenAI-совместимый SSE endpoint. Семь запросов включают ведущего и служебную генерацию; наблюдалось до шести одновременных HTTP-потоков. Выполняется ввод текста во время генерации, снимаются CPU profile, DOM/раскладка и задержка до следующего кадра. Реальные ключи и платные API не используются.

Одна пара последовательных запусков одинакового сценария (`baseline` → `optimized`):

| Показатель | До | После |
| --- | ---: | ---: |
| Задержка ввода, медиана | 25,3 мс | 15,6 мс |
| Задержка ввода, 95-й процентиль | 163,6 мс | 55,2 мс |
| Время JavaScript в интервале | 1,656 с | 0,996 с |
| Пересчёты раскладки | 226 | 144 |
| Пересчёты стилей | 825 | 646 |
| Наблюдавшиеся задачи свыше 50 мс | 1 | 0 |

Это измерения локального сценария, а не гарантия ускорения любой модели или любого размера истории. Профилирование само добавляет нагрузку. Время ответа провайдера и компиляция пользовательских проектов здесь не ускоряются. Запуск управляемых процессов из Electron по-прежнему имеет собственные накладные расходы.

## Проверки поведения

- `tests/stream-publication.test.mjs`: 1000 последовательных дельт, ограниченная частота публикаций, сохранение порядка и полного текста, немедленное завершение, отмена обеих фаз, работа скрытой страницы. Проверяется совпадение тестируемого фрагмента с установленным модулем.
- `tests/ui-performance.mjs --team --verify-scroll`: реальная параллельная команда, ввод во время генерации; отдельный ход проверяет сохранение позиции читателя при продолжающейся генерации и наличие конца ответа.
- UI smoke проверяет обычный чат, черновик, переключение проектов, профили агентов, настройки, темы и компактное окно.
- Обе проверки публикации прошли под Electron из подготовленного ASAR. Обычный UI smoke прошёл; отдельный тест трёх реальных локальных ходов подтвердил сохранение видеокарточек после новых сообщений, перезагрузки и повторного открытия истории, а также подготовку черновика повтора.

Для legacy Electron обновление публикуется как `app/resources/app.update.asar`.
Rust/WebView2 загружает модули из `source/dsh`; изменение файлов не перезапускает
уже загруженный сервер и агента. Текущие процессы ради применения правок не завершаются.

## Иконки и запуск Rust/WebView2

Основные примитивы уже встроены в JS, CDN для них не требуется. У Moonlight была
отдельная загрузка `qcoderi-sidebar-glyphs.svg` и рассинхрон ссылок source/assets.
Теперь 18 символов встроены в HTML перед React root, а sidebar/session ссылаются
на `#qcoderi-glyph-*` в том же документе. Сборка создаёт одну таблицу уникальных ID.

`native/startup-cache.mjs` добавляет ленивый LRU-кеш только поставляемых статических
ресурсов (до 16 МиБ, 96 записей, 4 МиБ на запись), MIME, ETag/304 и настоящий 404.
HTML, plugin graph, API, credentials, настройки и история в него не входят.
Сначала проверяются capability/origin. Изменение файла инвалидирует кеш; выход
симлинка за dist не разрешён. Bytecode cache Node включается до импорта host,
но его недоступность не препятствует запуску. Он не сохраняет результат загрузки
профиля и не заменяет свежую сборку конфигурации.

Удалены стартовое уведомление Harness и окно обязательной настройки DeepSeek:
это удаление компонентов, store и регистрации, а не CSS-скрытие или автоматическое
подтверждение. Произвольные провайдеры и редактор ключей доступны в «Модели».
`scripts/remove-upstream-onboarding.py` воспроизводит удаление при сборке.

Проверки:
- `tests/startup-performance.test.mjs`: 13 тестов кеширования, инвалидации,
  символов, запрета выхода по ссылке и сохранения авторизации/CSP;
- `tests/provider-neutral-startup.test.mjs`: удаление модалей и текста,
  реальная регистрация настроек моделей и идемпотентность патча;
- `tests/build-runtime.test.py`: упаковка всех source-owned helper-модулей,
  отсутствие дубликатов SVG и исключение тестового browser profile из поставки;
- `scripts/preview-next-ui.mjs` + `inspect-next-ui.mjs --after`: отдельный host,
  чистый профиль и фоновый Chrome; HTTPS блокируется, проверяются реальные SVG
  и интерактивный root без onboarding. Скриншот снимается desktop-инструментом.

В loopback-fixture повторный запрос получил 304 с **0 байт тела вместо 5996**.
В интегрированном тестовом UI: нет внешних запросов, ошибок ресурсов и uncaught
exceptions, все проверяемые sidebar/session SVG имеют геометрию. Это не benchmark
полного холодного запуска Windows/WebView2: стабильный процент ускорения не измерен.
Остались загрузка plugin bundle (~12 МБ в наблюдавшемся тесте) и ожидание host до
создания окна; их безопасное разделение — отдельная работа, не решённая кешем.
