# Unreal Engine 5 — работа из чата

В режиме **Проекты** выбери папку с `.uproject`, начни **новый** диалог и выбери профиль **Unreal Engine 5**. Модель выбирается отдельно обычным переключателем: подходит подключённая модель с вызовом инструментов, в том числе твой вариант DeepSeek. Профиль не меняет провайдера, ключ или модель. В уже открытом диалоге профиль не подменяется.

Пример первого сообщения:

> Подключи этот Unreal-проект. Движок лежит в G:/UE/UE_5.7. Подготовь мост, собери его и скажи, когда открыть редактор.

Агент вызывает `unreal_setup`: копирует плагин в `Plugins/QCoderIBridge`, сохраняет резервную копию `.uproject`, включает плагин. Для установленной UE **5.7.4** в поставке есть готовая DLL: при совпадении версии, BuildId и контрольной суммы исходников она устанавливается автоматически (`prebuilt_installed: true`). Затем достаточно открыть проект в UE. Движок ищется в `UE/UE_5.x` на диске проекта и `Program Files/Epic Games/UE_5.x`.

Если совместимой DLL нет, агент вызывает `unreal_build_bridge`. На время установки/сборки закрой Unreal Editor. Сборка идёт в фоне; агент должен дождаться `job_output`, проверить успех и только затем предложить открыть проект в UE. После открытия `unreal_status` должен вернуть `connected: true`.

Сборка редакторского плагина для другой версии требует C++ Build Tools и Windows SDK, совместимых с версией UE. Писать C++ игрового проекта или переводить игру с Blueprint на C++ не требуется. Исходники плагина входят в поставку; готовая универсальная DLL для всех UE не поставляется. После смены версии движка плагин нужно пересобрать. Настройка среды: [документация Epic](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-visual-studio-development-environment-for-cplusplus-projects-in-unreal-engine).

Можно собрать вручную после установки плагина:

```powershell
& 'G:/QCoderI/harness-base/assets/unreal/Build-Bridge.ps1' -ProjectFile 'G:/MyGame/MyGame.uproject' -EngineDirectory 'G:/UE/UE_5.7'
```

## Что доступно

- Просмотр уровня, создание акторов, Static Mesh, положение, вращение, масштаб и удаление.
- Blender в фоне с редактируемым `.blend`, проверкой сетки и рендерами в чат. Импорт статической геометрии из FBX и текстур из PNG/TGA/JPEG, сборка материала и назначение на слот Static Mesh.
- Поиск ассетов, чтение и изменение редактируемых свойств объектов/компонентов.
- Создание Actor Blueprint и Widget Blueprint, переменных, event/call/get/set-нод, событий кнопок `OnClicked`, соединений пинов и значений по умолчанию.
- Создание дерева UMG, текста, кнопок и панелей, изменение текста, размера/гарнитуры шрифта, размещение дочерних элементов CanvasPanel.
- Проверка дерева виджетов и графов, компиляция с настоящими сообщениями UE, отдельное сохранение ассетов, текущего уровня или нового уровня по пути `/Game/Maps/...`.

Пример:

> Сделай `/Game/UI/WBP_MainMenu`: заголовок «Забытый город», кнопки «Играть», «Настройки» и «Выход». Заголовок 48, кнопки 24. Сначала изучи проект и доступные шрифты. Собери дерево, свяжи события кнопок в Blueprint, проверь компиляцию и сохрани изменённые ассеты. Объясни, где меню подключено к игре.

`unreal_command(action: "describe")` возвращает точные аргументы всех команд. Граф остаётся обычным редактируемым Blueprint, интерфейс — Widget Blueprint в Designer. Размеры сцены в сантиметрах, вращение — `[pitch,yaw,roll]`.

## Blender и команда

Мост 0.3 добавляет `scene_preview: true` в `unreal_status`. Команда `scene_inspect` показывает камеры и свет текущего уровня, параметры Post Process Volumes и назначенные скелетным компонентам ассеты. `unreal_viewport` возвращает PNG активного перспективного viewport в чат. Для проверки конкретной камеры сначала пилотируй её в редакторе. Для захвата нужен редактор с графикой. `animation_inspect` показывает скелет, длительность, частоту и число отсчётов импортированного клипа.

Например, поручите сделать игровой объект по референсам и поставить его на уровень. Ведущий распределит геометрию и UV, текстуры и независимые работы над Blueprint между исполнителями. Интеграция стартует после готовности модели и карт. Каждому исполнителю назначаются свои файлы, а обращения к общему редактору идут под ресурсом `unreal-editor`.

Для импорта нужен `asset_pipeline: true` в `unreal_status`. Если проект использует старый мост, закройте UE, обновите его через `unreal_setup` и снова откройте проект. `asset_import` принимает файл внутри папки проекта и новый путь пакета `/Game/…`. Для цветовой текстуры выбирайте `color`, для карт roughness/metallic/AO — `linear`, для нормалей — `normal` с конвенцией DirectX. `material_create` связывает карты с обычным редактируемым материалом UE, а `mesh_set_material` назначает его на указанный слот. Сохраните материал, текстуры, меш и уровень отдельными командами. Импорт через мост рассчитан на статические модели.

Шрифты задаются импортированными UE-ассетами Font/FontFace; сначала импортируй `.ttf/.otf` через Content Browser. У `widget_font` нужен путь ассета, а не путь файла Windows. Сейчас команда рассчитана на `TextBlock`; RichTextBlock и стили CommonUI отдельного API не имеют. `widget_layout` работает с CanvasPanelSlot. Прочие редактируемые свойства можно читать/менять через `object_inspect` / `object_set` в текстовом формате UE.

Есть примитивы создания логики; автоматическое подключение любого меню к любому GameMode не гарантируется. Модель должна исследовать существующие графы и явно собрать цепочку показа меню, ввода и обработчиков. Создание UMG-дерева само по себе не показывает меню в игре. Мост не поддерживает произвольные виды нод, удаление/перестройку графов, импорт шрифтов из файлов и проверку кликов в PIE.

## Как устроено подключение

Мост — editor-only модуль UE, исключённый из игрового runtime. Он читает атомарные JSON-запросы в `Saved/QCoderI/Bridge` на основном потоке редактора и возвращает результат. Внутри UE нет API-ключей, сетевого сервера или интерпретатора произвольного кода. Доступ к папке проекта равнозначен доступу к управлению мостом; это локальная интеграция, а не граница безопасности между пользователями Windows.

Каждый запуск редактора имеет отдельный идентификатор, запросы имеют срок действия. UE забирает запрос переименованием в `.processing` и никогда не переигрывает его после сбоя. Отмена удаляет ещё не забранный запрос. Если редактор уже начал действие, отмена не откатывает его: после тайм-аута сначала проверь состояние. Файлы `.processing` после аварии и поздние ответы могут остаться в `Saved`; они не выполняются повторно.

Во время PIE команды блокируются. Редактирование свойств/графов/виджетов обёрнуто в транзакции UE. Сохранение явно запускается отдельными командами; создание ассета не следует считать полностью откатываемым одним Undo. Если `blueprint_compile` возвращает `compiled: false`, исправь ошибки прежде, чем сохранять.

## Проверки

`tests/unreal.test.mjs` проверяет установку с сохранением настроек, запросы/ответы, отмену, тайм-ауты, устаревший редактор и регистрацию инструментов через настоящий runtime QCoderI. Полный AgentLoop делает вызов UE-инструмента, получает ответ и передаёт его той же выбранной модели. Транспорт редактора в этом тесте имитируется, платные API не вызываются. Проверяется и установка из упакованного Electron `app.asar`.

`tests/unreal-editor.mjs` — отдельная проверка с настоящим UE: запускается вручную с путём тестового `.uproject`, куда скопирован собранный мост, и уже открытым редактором. Использует только изолированный тестовый проект. Итоги реальной сборки/проверки фиксируются отдельно, а наличие исходников не означает поддержку всех версий UE.

С флагом `--blender-assets` тест дополнительно гоняет экспорт из Blender в UE. На Blender 5.1.0 и UE 5.7.4 проверены FBX с сохранением масштаба (2 м → 200 см), импорт PNG в режимах color/linear/normal, подключение трёх карт, назначение материала на слот меша и сохранение меша, текстур, материала и уровня.

Локально проверено на **UE 5.7.4 / Win64**, BuildId `47537391`: создание/перемещение актора и сохранение `.umap`, Actor Blueprint с переменной и соединёнными нодами, Widget Blueprint с текстом, Font Roboto (48/24), Canvas-размещением, событием OnClicked и соединённым обработчиком, а также цепочка Create Widget → Add to Viewport. Все проверенные Blueprint компилировались с **0 ошибок / 0 предупреждений**, ассеты сохранены на диск. Редактор работал с NullRHI; реальные клики и внешний вид в PIE этой проверкой не подтверждаются. Платные запросы к DeepSeek не отправлялись.

Для фонового теста использовался временный запуск с `-DDC-ForceMemoryCache -ddc=InstalledNoZenLocalFallback`, потому что локальный Zen-кэш в окружении не отвечал. Это параметры тестового процесса, настройки игровых проектов не менялись.

Готовая DLL собирается через `Build-Bridge.ps1` локальным компилятором без UBA и без большого общего PCH. `scripts/bundle-unreal.py --engine ... --compiled-plugin ...` упаковывает её с BuildId, хешем бинарника и хешем исходников. При изменении C++ устаревшая готовая DLL автоматически перестаёт подходить, пока её не пересоберут.
