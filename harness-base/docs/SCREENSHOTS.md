# Снимки экрана в чате

В режиме «Проекты» доступен `take_screenshot`. Системные инструкции требуют самостоятельно использовать его, когда нужно проверить или продемонстрировать визуальный результат текущей работы. Отдельная команда пользователя на скриншот не нужна. Это решение агента по содержанию задачи: для чисто текстовых и серверных задач без видимого результата кадр не требуется. Результат содержит PNG как полноценное вложение: он сразу показан в ленте, открывается в просмотрщике и передаётся модели на следующем ходе. В обычном режиме «Общение» инструменты по-прежнему отключены.

Пример задачи: «Исправь интерфейс и продемонстрируй результат». Агенту предписано сначала открыть нужный результат, выбрать соответствующее окно или область, снять его и подписать, что проверено. Активным может оказаться само QCoderI; инструмент снимает фактически выбранное окно, не переключая приложения. Генерируемые иллюстрации не заменяют снимок реального результата.

Параметры:

| Параметр | Значение |
| --- | --- |
| `target` | `primary` по умолчанию; `all` — весь рабочий стол; `active_window` — видимая часть активного окна |
| `x`, `y`, `width`, `height` | Все четыре сразу: область внутри выбранной цели; абсолютные координаты рабочего стола, включая отрицательные для других мониторов |
| `delay_ms` | Ожидание отрисовки 0–3000 мс |
| `caption` | Подпись до 240 символов |

Каждый вызов снимает один кадр. Указатель мыши не рисуется отдельно. Размер ограничен 8192 px по каждой стороне, 64 Мп и 20 МБ PNG; слишком большой рабочий стол нужно снимать по областям. Хранилище вложений может нормализовать большой кадр; исходные границы сообщаются рядом с изображением. Текстовая модель может показать снимок пользователю, но анализировать его сможет модель с поддержкой изображений.

Захват выполняет Windows GDI (`Graphics.CopyFromScreen`) в отдельном скрытом процессе штатного Windows PowerShell. Установка утилит не нужна. Программа PowerShell фиксированная; параметры передаются как JSON, подпись не исполняется. Есть тайм-аут и отмена. Файл не создаётся в рабочем проекте: PNG записывается через штатный AttachmentStore и привязывается к результату инструмента в истории. Перезагрузка интерфейса не повторяет захват.

Код: `assets/team/screen-capture.js`, `assets/team/screenshot.js`, `assets/screenshot-view.js`. `scripts/apply-screenshots.py` подключает инструмент к настольному хосту и добавляет карточку в чат через штатную галерею вложений. Карточка видна и при свёрнутой истории инструментов. `scripts/build.py` воспроизводит установку.

Проверки: `tests/screenshots-native.mjs` проверяет настоящий кадр Windows, границы, отмену, поток AgentLoop → инструмент → сохранённое изображение → следующий ход модели, а также отсутствие инструмента в обычном чате. `QCODERI_SCREENSHOT_UI=1 node harness-base/scripts/smoke.mjs` проверяет готовое приложение с локальным API: реальный вызов инструмента, PNG в следующем запросе модели, сразу видимую картинку в чате, перезагрузку и крупный просмотр. Пользовательские подключения для этой UI-проверки не используются.
