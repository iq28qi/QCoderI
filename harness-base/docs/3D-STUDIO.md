# Профиль 3D Studio

Выберите «Агенты → Профили агентов → 3D Studio», рабочую папку и новый диалог. Уже начатые диалоги сохраняют прежний профиль. Можно приложить фото, несколько ракурсов и описание назначения объекта. Пример: «Сделай по этим фото редактируемую модель для Unreal, проверь пропорции и материалы, покажи общий ракурс и детали».

Профиль содержит стандартные рабочие инструменты, управление приложениями, скриншоты, генерацию изображений и инструменты Blender. Он работает с выбранной моделью чата. Для чтения референсов и рендеров нужна модель с поддержкой изображений. Фото загружаются штатным способом через поле сообщения; `share_image` отправляет готовый рендер в чат, `take_screenshot` показывает настоящее окно редактора. Генерация Seedream/Krea используется для 2D-концептов, материалов и текстур, а не выдаётся за готовую геометрию.

## Качество

Профиль требует сначала разобраться в силуэте, пропорциях, масштабе и назначении, затем проработать форму и детали. Проверяются нормали, вырожденные полигоны, случайные пересечения, материалы, UV и ограничения целевой платформы. Для печати важны толщина и замкнутость; для анимации — деформация и топология; для игровых моделей — бюджет, LOD/коллизии по задаче.

Обязательный рабочий цикл в инструкциях: черновой рендер → открыть и осмотреть → сравнить с референсом → исправить конкретные недостатки → проверить общий и дополнительный ракурс/деталь. Для объёмного объекта нужен также контроль обратной стороны. Агент должен сам показать реальные кадры до итогового ответа, сохранить редактируемый результат и передать запрошенный экспорт. Это проверяемый процесс, а не гарантия идеального вида любого объекта; качество зависит от задачи, исходных данных и возможностей выбранной модели.

## Blender

Команда `/blender` в профилях «3D Studio», «Unreal Engine 5» и «Команда QCoderI» показывает установленную версию и возможности по моделированию, ригу и анимации. Она работает локально без вызова модели.

`blender_status` находит установленный Blender и читает его настоящую версию. Проверяются `BLENDER_EXECUTABLE`, обычные каталоги установки, `G:/Blender` и PATH; путь можно указать явно. Автоматической установки нет.

`blender_run` принимает `script_file` (`.py` в проекте), необязательный `blend_file`, `render`, `views`, путь к Blender и тайм-аут 10–1800 секунд. Он создаёт фоновое задание. Агент собирает `job_output(wait:true)`, затем открывает рендер через `share_image`. Каждому запуску выделяется новая папка `QCoderI-3D/run-*` с `scene.blend`, `inspection.json`, `render.png` при запросе и скриптами воспроизведения. Папка вывода проверяется на принадлежность проекту, включая ссылки каталогов.

При `views: true` дополнительно создаются `render-front.png`, `render-side.png`, `render-back.png` и список `views.json`; пути возвращаются в результате задания. Это облегчает проверку объёма с нескольких сторон. После рендера ракурсов исходное положение камеры восстанавливается. Это несколько рендеров, поэтому времени требуется больше, чем на один кадр.

Передай `frames`, например `[1, 12, 24]`, чтобы снять выбранные моменты движения с активной камерой и светом сцены. Список PNG будет в `frames.json` и отчёте задания. `inspection.json` показывает диапазон кадров, FPS, камеры, свет, Actions/NLA, риги, вершины без весов и Shape Keys.

`qc.export_unreal_fbx(path, objects, animation=True)` экспортирует явно выбранные меши и арматуры с запеканием текущей шкалы времени. При наличии Shape Keys модификаторы сетки при экспорте не применяются. После импорта в UE проверь масштаб, скелет и клипы.

Скрипт получает `bpy`, `qc` и `QC_OUTPUT_DIR`:

```python
subject.data.materials.append(qc.material('Paint', (.1, .3, .5, 1), roughness=.3))
qc.studio([subject], quality='preview')
report = qc.audit()
```

`qc.studio` добавляет студийный пол, камеру, key/fill/rim-свет, Cycles CPU, denoising и AgX при наличии. Preview — 768 px / 32 samples; final — 1536 px / 128 samples. Это стартовые настройки, которые нужно адаптировать к сцене. `qc.audit` проверяет базовую сетку: число полигонов, non-manifold-рёбра, изолированные вершины, нулевую площадь граней, UV, материалы, масштабы и наличие камеры/света. Открытая поверхность может быть намеренной; отчёт не исправляет сцену и не заменяет визуальную проверку модификаторов.

Повторная установка студии удаляет только объекты, помеченные самим помощником, и сохраняет пользовательские объекты с любыми именами, включая `QC_…`. Мир копируется перед изменением света. Отчёт также показывает количество вершин и граней после модификаторов и предупреждает об отражённом масштабе. Скрипт может отдельно вызвать `qc.render_views(QC_OUTPUT_DIR)`.

Blender запускается отдельным процессом через [штатные параметры CLI](https://docs.blender.org/manual/en/latest/advanced/command_line/render.html), без автоматического исполнения скриптов загружаемого `.blend`; явно переданный проектный скрипт выполняется с правами текущего пользователя. Обёртка сохраняет новую версию, однако сам авторский Python имеет обычный доступ к файлам. Несохранённые изменения уже открытого Blender не затрагиваются; перед открытием нового результата нужно учитывать текущую сцену. Другие 3D-приложения доступны через GUI и их штатные API/скрипты.

Проверено на установленном Blender 5.1.0: создан настоящий `.blend`, выполнен CPU-рендер, проверены материал/камера/свет и отчёт сетки, повторно открыт сохранённый проект, обнаружена ошибка Python с ненулевым кодом. Настоящие Tools/Jobs запускают Blender, собирают результат и отправляют PNG через `share_image`. AgentLoop получает фото-референс и изображение работы; проверяется и доступность нового профиля в штатном каталоге.

## Asset Specification и машинные quality gates

`blender_run` принимает необязательный `asset_specification` версии 1. Назначение
`generic` / `static` / `character` / `print` определяет исходные требования; их можно
уточнить явно. `subjects` — точные имена mesh-объектов. Без списка помощники студии
исключаются из проверки. Длины и размеры задаются в метрах, площади — в м²,
полигональный бюджет — в **треугольниках после модификаторов**.

```json
{
  "name": "UE5 prop",
  "purpose": "static",
  "subjects": ["Product"],
  "units": {"system": "METRIC", "meters_per_unit": 1},
  "requirements": {"uv": true, "materials": true, "reference": true},
  "limits": {"max_triangles": 50000, "dimensions_m": {"max": [2, 2, 2]}},
  "export_format": "fbx"
}
```

Это пример контракта, не универсальный бюджет: целевую платформу и размеры следует
согласовать по задаче. Неизвестные поля и ошибочные значения отклоняются до запуска.

В каждом `run-*` дополнительно сохраняются:
- `asset-specification.json` — нормализованные требования;
- `quality.json` — gates со статусами `pass`, `fail`, `pending`, `not_applicable`,
  конкретными defects и указанием недостающих измерений;
- `evidence.json` — SHA-256 фактических артефактов и привязка к запуску/исходникам.

Технические проверки включают измеренную базовую/evaluated-сетку, вырождения,
отдельные вершины/рёбра, требования manifold/UV, материал и доступность изображений,
масштаб, мировые границы в метрах и заданный бюджет. При наличии скелета проверяются
измеримые сведения о весах; это не доказательство корректной деформации.

**`completed` фоновой задачи не означает готовность ассета.** Успешное сохранение
`.blend`, PNG или FBX не засчитывает визуальное сходство, качество UV-развёртки,
крайние позы рига и импорт в UE. Пока такие проверки не связаны с подтверждённым
результатом независимой проверки, соответствующие gates остаются `pending`,
а `ready_for_export` — `false`. `quality_review` уже может дать агенту замечания,
но его текст не превращается автоматически в подтверждённый pass `quality.json`.
Автоматическая художественная корректность, ретопология и отсутствие всех
самопересечений/проблем толщины не гарантируются.
