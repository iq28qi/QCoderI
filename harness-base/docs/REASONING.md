# Автоматические уровни рассуждений в чате

Под полем сообщения нажмите имя модели → **Уровень рассуждений**. Выбор действует на следующие запросы, сохраняется в настройках и передаётся дочерним агентам штатным механизмом наследования. Текст системного промпта и сообщений от уровня не меняется.

**По умолчанию** оставляет выбор серверу: поля управления рассуждением не отправляются. **Выключено**, если модель поддерживает этот режим, отправляет явное выключение. Это разные режимы.

Управление находится только в чате. В настройках провайдера нет формы уровней, переключателей формата или таблицы значений API.

Приложение автоматически читает `GET /models` выбранного подключения: стандартный массив `data`, массив `models` или расширенную карту моделей. Явные списки уровней из ответа сервера имеют приоритет; поддерживаются `effort.supported_levels`, перечисления `reasoning_effort` и аналогичные поля возможностей. Поэтому имя модели может быть произвольным псевдонимом. Для имён без таких данных используются штатный каталог и подсказки по известным семействам:

| Семейство | Варианты | Передача |
| --- | --- | --- |
| Kimi K3 | Низкий, высокий, максимальный | `reasoning_effort` |
| DeepSeek V4 / Flash | Выключено, низкий, высокий, максимальный | Chat: `thinking.type` и `reasoning_effort`; Responses: `reasoning.effort` |
| GPT 6 | Низкий, средний, высокий, очень высокий, максимальный; выключение для Sol/Luna, кроме 6.1 Sol | Chat: `reasoning_effort`; Responses: `reasoning.effort` |
| Claude 5 | Низкий, средний, высокий, очень высокий, максимальный | Messages: adaptive thinking + `output_config.effort`; совместимый Chat: `reasoning_effort` |
| GLM 5.3 | По умолчанию / включено | `thinking.type: enabled`; регулируемые уровни не заявлены |

Список моделей запрашивается с ключом и заголовками именно этого подключения. Кэш разделяется по протоколу, Base URL и отпечатку ключа/заголовков. Успешные ответы кэшируются на 10 минут; недоступный список повторно проверяется через минуту. Запрос ограничен двумя секундами и 4 МБ. Проверочных генераций нет.

На вопрос «какая ты модель?» чат показывает имя из последнего ответа текущего подключения и выбранного ID, если провайдер прислал отдельный идентификатор. Иначе используются явные поля upstream или canonical в каталоге подключения. Если API возвращает только выбранный ID, чат сообщает, что фактическая модель неизвестна. Вопрос не запускает генерацию.

Если API отдаёт только непрозрачный идентификатор и не раскрывает уровни или исходную модель, достоверно определить поддержку нельзя. В чате показывается «Авто · API не сообщает доступные уровни», а запрос сохраняет серверное поведение по умолчанию. Видеомоделям не назначаются текстовые уровни. Доступность конкретного параметра зависит от реализации шлюза.

Код: `assets/reasoning-policy.js`, `assets/reasoning-adapter.js`, `assets/reasoning-adapter-method.js`. `scripts/apply-reasoning.py` воспроизводимо устанавливает изменения и удаляет прежнюю форму; `scripts/build.py` вызывает его при сборке. Пользовательские ключи и существующие диалоги не мигрируются.

## Проверка

`tests/reasoning-native.mjs` использует настоящий AgentLoop, адаптер, SDK и сериализацию запросов, перехватывая HTTP внутри процесса. Проверяет три протокола, значения в 19 запросах, неизменность сообщений, отличие default от off, отказ до генерации для недопустимых уровней, сохранение/сброс, автоматическое распознавание псевдонимов, изоляцию кэша при смене ключа/Base URL и наследование дочерним агентом. Включён в `scripts/test.ps1`.

`QCODERI_REASONING_UI=1 node harness-base/scripts/smoke.mjs` проверяет настоящий Electron: меню Kimi, выбор максимального уровня, запись в YAML, перезагрузку, сброс, отсутствие формы в настройках и получение уровней произвольного псевдонима от локального API. `QCODERI_TEST_APP` выбирает отдельную тестовую сборку. Платных запросов нет.
